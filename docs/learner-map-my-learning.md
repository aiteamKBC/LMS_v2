# Learner’s Map and My Learning

Implement two entry points to the same subjects, activities and progress, using the learner navy and purple palette. My Learning follows the reference catalogue layout; Learner’s Map follows the alternating weekly timeline.

- `/learner/my-learning` displays subject cards, programme statistics, search, progress filters, sorting, grid/list views, Continue learning and upcoming deadlines.
- `/learner/learning-plan/modules` displays the current module’s weeks with a module selector. Current placement and teaching dates use the same `learnerHeaderPlan` rules as the dashboard: programme/cohort/group compatibility, and `start_date <= today <= end_date`, using the UK calendar date (`Europe/London`). Overlapping modules are all marked current. Activity completion and imported activity dates never make a module current.
- Outside an active teaching period, the map can open the next or most recent planned module, explicitly labelled **Next module** or **Previous module**, with its training-plan dates in the banner. Missing/invalid/unavailable dates do not invent a current module. Learners can still select materials manually; a manual selection does not change which modules are current.
- Both routes also support `/:kind/:id` for the existing learner/staff context.
- `subject` identifies the unified subject. Imported subjects use `legacy:<groupId>` and current subjects use `current:<moduleId>`. Builder links resolve current module links to a merged imported subject when appropriate.
- `week` identifies the selected calendar week or assigned week. `week=current` is resolved after activity delivery dates load: the week containing today's UK date wins, including completed weeks; only when no dated current week exists does it fall back to the next unfinished week. A delivery date without an explicit range uses its Monday–Sunday calendar week. Invalid dates and unverified upload dates do not establish a current teaching week. Selecting another module clears the previous week; browser Back restores the previous selection.
- Dashboard Continue learning links to the same My Learning route with `week=current`, preserving the learner identity and the planned module's Builder/imported mapping. The catalogue Continue learning action uses the same rule and keeps the current module selected even when it is complete.
- Opening a map week displays only that week’s activities, using the existing material player and iframe. Native videos, quizzes and components keep their existing player routes.
- Opening a catalogue subject with available Builder content goes straight to its existing activity player. It chooses an unfinished available activity in the current UK calendar week, or an available activity for review when that week is complete; outside a dated current week it uses the next unfinished week. Explicit week links retain that week. Browser Back returns to the catalogue without an intermediate month/week screen. Imported-only materials and unpublished weeks retain their material browser.
- The activity player keeps the open week at the top of its sidebar and all module weeks below. Each four teaching weeks retain their group, named with consecutive calendar months starting at the module's Training Plan start month (for example, August 2026, September 2026, October 2026). The shared player sidebar reads the existing training-plan schedule and resolves the module by its activity module IDs, using a unique title only for older records without IDs. Missing, invalid or unavailable plan dates retain Month 1, Month 2, etc. until dates are available. Introductions, extra activities and module assessments do not consume teaching-week positions. Each week still expands in place before the learner chooses an activity.
- Weekly cards keep activities crossing a month boundary together. Introductions, extra activities and undated activities stay distinct. Assigned empty weeks remain visible with a materials-pending message.
- Existing subject deduplication and completion rules remain shared. Filters never change progress denominators. Programme statistics keep the existing metrics API; deadlines come from the existing overview API. No dates, deadlines, KSB mappings or OTJH values are invented.
- Existing read-only and completion permissions remain in the learner workspace and material players.

No database changes or migrations are needed.

Layout uses the available content width after the workspace sidebar, with a shared page width for the header, statistics, loading placeholders and cards. The sidebar panels move below the subjects on smaller screens; the timeline becomes a single column on mobile.

The approved weekly mock-up is implemented using the existing `learner-theme.css` navy, purple and success tokens. The map banner shows the selected module and its actual completed-week count, followed by the module selector, activity search and My Learning link. The banner keeps its module-wide totals when searching; empty assigned weeks never count as complete. Introductions, extras and undated groups use a section count. Longer modules use a compact progress bar instead of an overflowing row of markers.

Week cards form a sequential journey, alternating left and right above 850 pixels of available content width and stacking below that. Each week begins below the preceding card with at least 36 pixels between stops, joined to the central path. Each card shows its existing dates, activity completion, planned OTJH and progress. Completed cards use green and Review week; the current or next unfinished available week is emphasised in purple with Continue week. Upcoming and unpublished materials remain visible. Opening a card keeps the same week/material route. Catalogue actions and fallback covers share the same palette.

Catalogue subjects use distinct accents from the existing purple, navy, green, gold, blue and rose palette. Colours are assigned using the full ID-sorted subject set, so search, sorting, progress filters and grid/list changes preserve each subject's colour. The accent appears in the fallback cover, icons, button, border and unfinished progress; completion badges and completed progress retain their status colours. The opened subject keeps the same fallback cover colour. Uploaded cover images remain visible.

Background refresh keeps the last successful learner and subject data. Ordinary focus/reconnect reads revalidate their own resources without invalidating all learner caches. Secondary totals, schedules and deadlines wait for the primary activity read. A previously verified learner page remains mounted during a connection failure with interaction paused until access verification recovers; first-time access still requires a successful check.

Validation: learner subject/material tests, map selection and browser-history tests, learner-page loading/failure tests, retained-page network recovery tests, and the production build. With the frontend running on port 3000, run `node scripts/learning-layout-smoke.mjs` from `frontend` for isolated browser checks at 320, 390, 768, 1024, 1280, 1440, 1920 and 2518 pixels. This uses synthetic API fixtures with the real app and workspace shell, checks grid/list layouts and connection recovery, and saves screenshots in `frontend/test-results/learning-layout`. It does not verify an authenticated learner's live backend data or write to the database.
