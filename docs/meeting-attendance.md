# Learner meeting attendance

The Monthly Coaching Meeting and Progress Review list pages feature today's scheduled meeting, then the next scheduled meeting. If none is scheduled, the card shows the earliest planned meeting as a scheduling reminder. Completed and cancelled meetings are excluded. Target dates are labelled explicitly; missing dates, duration and location are not invented.

The card displays the coach/reviewer, programme, date, start/end time, duration and online meeting link when recorded. Progress Reviews also show the learner's line manager and recorded learner-signature state. The existing schedule/reschedule and detail views remain available. Attendance actions also appear alongside Status in the desktop table and mobile meeting rows.

`GET /learner_api/meeting-attendance/<kind>/<learner_id>/` resolves records with the same source precedence as the list pages: imported learner review history when present, otherwise the learner's programme calendar. Imported records obtain duration and meeting links only through their durable review-id booking key. Matching another booking's date/title is insufficient. Other imported review types remain in the Reviews history, but do not receive Progress Review attendance actions.

`POST /learner_api/meeting-attendance/<kind>/<learner_id>/attend/` accepts a meeting ID and requires CSRF plus learner-owner/admin access. It resolves the date and duration on the server, permits only the meeting's local calendar date, and rechecks eligibility after obtaining the existing learner-ledger lock. The resulting attendance event credits the full recorded duration once. It does not complete or sign the review form. Monthly Logs reuse the meeting source reference, so a later coach completion does not add a second credit; imported review identity also survives a changed booking key.

Schedule and Reschedule on both list pages (featured card, desktop table and mobile rows) open the shared compact Book session dialog in place. It shows the selected Session, Day and Time, plus Cancel and Book session (or Save new time). Rescheduling preselects the current appointment and preserves its recorded duration. Closing or pressing Escape restores focus to the initiating control.

The dialog revalidates the learner calendar and resolves the exact event key or imported review ID before enabling submission. Generated rows use their own event key; imported first bookings use review ID and assignment month; existing imported bookings use their durable calendar key with PATCH. No matching by date is allowed. The existing booking/reschedule APIs enforce conflicts and calendar synchronization, while the form applies existing booking-date restrictions and reports server errors without losing entered values. Successful saves refresh the list and attendance data, retaining Microsoft synchronization warnings.

The shared Report Absence dialog uses `scope=meetings` and preselects the exact appointment. Meeting absences require a reason and confirmation; lecture recording/catch-up choices are omitted. The existing coach absence-review workflow stores the report. Rescheduling remains an explicit action. Absence identity includes the appointment date/time, so reporting the old appointment does not block attending its replacement.

No database migration is needed. Existing review records, calendar events, absence reports and learner progress entries are used. Imported meetings without a recorded booking duration show “To be confirmed” and cannot receive an invented hour credit.

Calendar sync failures preserve the locally scheduled date, time and status. Calendar GETs must not save records or cancel Graph events. Saved appointments remain in their organiser's calendar even when the learner's current caseload or generated cycle changes; visible date ranges are applied after saved dates replace target dates. Imported Progress Review bookings are included alongside imported MCM bookings, and persisted/generated rows are deduplicated by event key.

Rescheduling a Microsoft event uses PATCH against its stored organiser and event ID. It preserves the existing event body and online-meeting configuration, including Microsoft's Teams joining information. Start/end properties are updated; the original invitation body is retained. Failed or partial responses keep the last known join URL, but a failed update remains marked failed even when an old link exists. Repeating the same requested date/time retries a failed sync. A local finalisation failure after updating an established event never deletes that event; recovery retains its ID and link for retry. Compensation on first creation still applies only to a newly created event.

Microsoft setup: use the application configured by `MICROSOFT_GRAPH_CLIENT_ID`, grant Microsoft Graph **Application** permission `Calendars.ReadWrite`, and grant tenant admin consent. If calendar access still returns `ErrorAccessDenied`, the Microsoft administrator must check Exchange application-access restrictions for the organiser's mailbox. Calendar consent does not repair code-level event/link handling. Regression coverage: `coach_api.tests_calendar_reschedule` and `learner_api.tests_booking_calendar`.

Both booking pages show the returned Microsoft warning and retain it on reload through calendar/attendance data. The featured card links to the exact saved date and calendar event; imported reviews use their durable booking key. Microsoft invitation status is separate from local scheduling status. An administrator must grant the booking application's required Microsoft calendar access when Graph returns AccessDenied; a local booking alone does not prove an external invitation was delivered.

Calendar regressions: `coach_api.tests_calendar_sync_visibility`, `learner_api.tests_booking_calendar`, `learner_api.tests_learner_calendar_cycle`, frontend `reviews/programmeSessions.test.tsx` and `calendar/page.test.tsx`. The imported MCM booking fixture includes its required review ID and checks that the owned review is updated.
