# برومبت تنفيذ مشاهدة تسجيلات Teams داخل الـLMS

## المطلوب

أكمل تشغيل مسار تسجيلات Teams بحيث يشاهد الطالب المحاضرة والـtranscript داخل الموديول، من نسخة محفوظة في Azure الخاص، دون الحاجة إلى فتح Teams. شغّل عامل النقل على سيرفر الـBackend بعد التحقق من المشاهدة والصلاحيات. تجربة العرض تكون داخل الصفحة كما في الأوديت؛ استخدم المشغّل الموجود ولا تستبدله بـiframe لمجرد تغيير التقنية.

## طريقة العمل الملزمة

- اقرأ `AGENTS.md` وحافظ على تغييرات الفريق الموجودة. لا commits أو push أو pull أو PRs أو migrations.
- نفّذ الخطوات بالترتيب. لا تبدأ خطوة تعتمد على سابقتها حتى تحقق شرط إغلاق السابقة وتسجّل الدليل. لا تعتبر `queued` أو نجاح الاختبارات المحاكية دليلًا على نجاح النقل أو التشغيل الحقيقي.
- إذا ظهرت مشكلة، أصلحها واختبرها داخل الخطوة نفسها. إذا نقص اتصال أو حساب أو بيئة لازمة، سجّل الخطوة `BLOCKED` واطلب المتطلب المحدد؛ لا تنتقل للخطوة التالية ولا تختلق نتيجة نجاح.
- لا تغيّر المواعيد أو الاجتماعات أو الدعوات أو قواعد الحضور والساعات. مشاهدة التسجيل لا تثبت حضور المحاضرة ولا تعتمد ساعات تلقائيًا.
- لا تغيّر `.env` أو مفاتيح الوصول أو صلاحيات Azure لتجاوز فشل. لا تجعل الحاوية عامة، ولا تكتب روابط SAS أو بيانات الطلاب في التقارير.
- أذونات التشغيل السابقة شملت تفعيل أرشيف النتائج ومزامنة `khalido 16` ثم `khaled`. لا تعتبرها إذنًا بمزامنة باقي المؤسسة أو إنشاء اجتماعات للاختبار. النشر المستهدف يحتاج تحديد السيرفر ونطاق الجدولة قبل تشغيله؛ لا تطلب إعادة إذن تم توفيره بالفعل.
- اختيار المحاضرة الأساسية من عدة recaps اقتراح منفصل، وليس قاعدة معتمدة في هذا التنفيذ. احتفظ بالسلوك الحالي الذي يعرض التسجيلات المرتبطة بالجلسة ولا تحذف أجزاء أو تستبعدها تلقائيًا.

## الخطوة 1: تثبيت الأساس المحلي

1. سجّل `git status --short` واقرأ التغييرات الموجودة قبل أي تعديل.
2. تتبّع الربط: الموديول ← مكوّن المحاضرة ← السلسلة والجلسة المحددة ← ملفات الأرشيف.
3. راجع صفحة الطالب، `SessionResults`، واجهات تنزيل الملفات، والتحقق من هوية الطالب وتخصيص الموديول له. غطِّ commercial وapprenticeship، والرفض للمستخدم المجهول أو لطالب آخر أو لموديول غير مخصص.
4. تحقق أن طلب المشاهدة يقرأ المحفوظ فقط؛ لا ينادي Graph ولا ينشئ مهام مزامنة، وأن ملفات الفيديو لها رابط قراءة مؤقت خاص بملف واحد.
   بناءً على موافقة صاحب المهمة على التحديث التلقائي، حدّث صفحة الحضور عند الرجوع للتبويب أو عودة الاتصال، مع دمج أحداث الرجوع المتتابعة ومنع الطلبات أثناء إخفاء التبويب. أبقِ آخر بيانات ناجحة ظاهرة أثناء إعادة القراءة، دون اعتماد حضور أو تعديل ساعات.
5. شغّل اختبارات Teams الأساسية واختبارات النتائج والمشغّل والمعاينة والحضور، ثم اختبارات Backend المعزولة التي لا تتصل بقاعدة بيانات أو خدمات خارجية.
6. عند تعديل كود Frontend شغّل type-check وlint، وعند تغيير الباندل أو الإعدادات شغّل build. لا تصلح ملفات غير مرتبطة لإخفاء إخفاق عام.

**شرط الإغلاق:** مسار المشاهدة والصلاحيات صحيح في الكود، والاختبارات المحلية المطلوبة ناجحة. دوّن أن هذا إثبات محلي فقط. اختبارات Django التي تحتاج قاعدة بيانات لها تحقق منفصل في الخطوة 2؛ لا تستبدلها بنتيجة اختبارات المحاكاة.

أوامر محلية آمنة بعد مراجعة إعداداتها، من جذر المستودع:

```powershell
npm --prefix frontend run test:teams
npm --prefix frontend run test -- src/components/feature/SessionResults.test.tsx src/pages/curriculum/module-builder/__tests__/learnerPreview.test.tsx src/pages/curriculum/module-builder/componentAuthoringModel.test.ts src/pages/learner/attendance src/pages/learner/video-watch --maxWorkers=2
python -B backend/curriculum_api/test_session_results_no_db.py
python -B backend/curriculum_api/test_calendar_actions_no_db.py
python -B backend/curriculum_api/test_calendar_state_no_db.py
python -B backend/curriculum_api/test_calendar_checks_no_db.py
```

## الخطوة 2: إثبات المشاهدة على البيئة المستهدفة

1. حدّد عنوان الـLMS والسيرفر والإصدار الذي يستخدمه الطالب فعليًا. لا تفترض أن عنوانًا قديمًا في التوثيق هو البيئة الحالية.
2. افحص إعدادات قاعدة البيانات والتخزين دون عرض أسرار أو تشغيل إصلاح تلقائي للـschema.
3. استخدم جلسة طالب اختبار مخوّلة وموديولًا مخصصًا له وتسجيلًا محفوظًا بالفعل. لا تستخدم جلسة Admin وحدها لإثبات تجربة الطالب، ولا تنتحل هوية طالب بإنشاء جلسة في قاعدة البيانات.
4. افتح الفيديو داخل الموديول: تحميل، تشغيل، إيقاف، تقديم، تكبير، transcript إن كان موجودًا. تحقق من منع الطلب المجهول ومنع الوصول إلى ملف خارج نطاق الموديول المسموح.
5. افحص أن الملف خاص وأن طلبات أجزاء الفيديو تعمل. رابط SAS المؤقت قابل للاستخدام ممن يمتلكه حتى انتهاء صلاحيته؛ الـiframe لا يمنع النسخ أو تسجيل الشاشة.
6. نفّذ اختبارات Django الموسعة فقط في بيئة اختبار معزولة محددة ومسموح بالكتابة إليها. لا تستخدم `manage.py test` على قاعدة البيانات المشتركة ولا migrations. وثّق الاختبارات المتعذرة صراحةً.

**شرط الإغلاق:** مشاهدة حقيقية ناجحة من حساب طالب على البيئة المحددة، مع إثبات حدود الصلاحية، وإغلاق بوابة اختبارات Backend المطلوبة. وجود MP4 في Azure أو استجابة HTTP ناجحة وحدهما لا يغلقان هذه الخطوة.

## الخطوة 3: تشغيل عامل النقل على السيرفر

1. بعد إغلاق الخطوة 2، حدّد طريقة استضافة الـBackend والجدولة الموجودة ونطاق الموديولات المصرّح به. لا تشغّل عاملًا عامًا على كل البيانات بإذن مزامنة موديولين فقط.
2. حضّر إعداد تشغيل يستخدم نفس إصدار الكود والبيئة المطلوبة، مع صلاحية الوصول إلى Graph وقاعدة البيانات وAzure ومساحة مؤقتة كافية للفيديو.
3. استخدم آلية الجدولة الموجودة كل خمس دقائق، وعامل curriculum واحد فقط. حافظ على جدولة coach الحالية، ولا تضف جدولة مكررة.
4. أثناء التفعيل المحدد استخدم `--live-session-id` لحصر المعالجة. الزر يضع طلبًا في قائمة الانتظار؛ العامل هو الذي ينقل الملف.
5. راقب انتقال مهمة مسموح بها من `queued` إلى `running` ثم `complete` وظهور النسخة المحفوظة. تحقق من عدم تعديل اجتماعات أو إرسال دعوات ومن عدم إعادة رفع الملفات الجاهزة.

**شرط الإغلاق:** العامل يعمل على السيرفر المستهدف بصورة دورية، بدليل من الجدولة والمهمة والملفات، ولا يعتمد على جهاز المطور أو فتح المتصفح. كتابة ملف إعداد أو نجاح تشغيل يدوي لا يكفيان.

## الخطوة 4: الاعتمادية والتسليم

1. اختبر انقطاع Graph/Azure وإعادة المحاولة والتشغيل المتزامن باستخدام mocks. لا تتعمّد تعطيل الإنتاج لاختبار الفشل.
2. تحقق من أن الفشل أو النقل الجزئي يظل ظاهرًا، وأن إعادة المحاولة لا تكرر الفيديوهات أو الحضور.
3. راجع انتهاء رابط المشاهدة وطريقة إعادة تحميله، دون تغيير صلاحية روابط مستندات الأوديت أو قواعد الحضور.
4. أعِد الاختبارات المناسبة بعد آخر تعديل وسجّل الأوامر والأعداد والنتائج وحدود الإثبات.
5. سلّم تقريرًا يفرّق بين: كود محلي، كود منشور، ملف محفوظ، مشاهدة طالب مثبتة، عامل دوري مثبت. اذكر تكلفة التخزين ونقل البيانات وقابلية مشاركة الرابط المؤقت دون الادعاء بوجود DRM.

**شرط الإغلاق:** كل خطوة سابقة مكتملة بالأدلة، مع بيان واضح لأي قيد متبقٍّ. لا تستخدم عبارة «شغال بالكامل» مع خطوة معلقة.

## سجل التنفيذ
