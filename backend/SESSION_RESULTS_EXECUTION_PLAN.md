# خطة تنفيذ واختبار نتائج جلسات Teams

آخر تحديث: 16 سبتمبر 2026. النطاق: الأدمن في Curriculum / Module Builder / Module Workspace، الطالب في Live Session والحضور، والكوتش في تعويض الغياب.

هذه قائمة متابعة تنفيذية. الكود موجود محليًا، لكن التفعيل واختبار التكامل الحقيقي لم يكتملوا. المراجع: [تفاصيل التشغيل وSQL](SESSION_RESULTS_OPERATIONS.md)، [نتائج الاختبارات وحدودها](SESSION_RESULTS_VALIDATION.md)، [سياسة المشروع](../AGENTS.md).

## طريقة متابعة الخطة

- `[x]` يعني أن البند المذكور نفسه تم، وليس أن المرحلة جاهزة للإنتاج.
- `[ ]` يعني مطلوب أو لم يُتحقق منه بعد. وجود الكود لا يكفي لإغلاق اختبار التكامل.
- بعد كل جزء نسجل: الملفات، أمر الاختبار، النتيجة، الدليل، والخطوة التالية. أي تعديل لاحق يعيد فتح الاختبارات المتأثرة.
- نحافظ على التعديلات الموجودة. لا commits أو push أو pull أو PRs، ولا migrations أو كتابة في قاعدة البيانات بواسطة الوكيل.
- SQL ينفذه المالك يدويًا. اختبارات Microsoft والملفات الحقيقية تحتاج بيئة اختبار محددة ومصرحًا بآثارها. إنشاء الكونتينر المصرح به لا يعني أن نقل التسجيلات اختُبر.

## قواعد ثابتة من طلب المستخدم

1. الحضور `1` بعد **أكثر من 180 ثانية** مثبتة في Teams. عند 180 ثانية أو أقل تكون النتيجة `0` بعد اكتمال التقرير.
2. الضغط على Join يسجل الطالب والجلسة للمطابقة؛ لا يثبت الحضور. نجمع فترات الاتصال دون تكرار الوقت المتداخل.
3. التقرير الناقص أو الهوية غير المؤكدة يظهران انتظارًا أو احتياج مراجعة؛ لا نخمن الغياب أو نطابق بالاسم فقط.
4. العذر المقبول يظل غيابًا `0` حتى إتمام Catch-up مرتبط بالجلسة وتأكيد الكوتش. الحجز أو مشاهدة الفيديو وحدهما لا يغيران الحضور.
5. نحفظ التسجيل والترانسكريبت وتقارير الحضور لدينا. فتح الصفحة يقرأ المحفوظ؛ المزامنة والنقل في الخلفية.
6. الأدمن يرى نتائج الجلسات ويصدر التقارير ويعاين المحتوى كطالب. الطالب يرى التسجيل داخل مكون Live Session وحضوره الشخصي فقط، ويغلق Join بعد نهاية الجلسة.

## الجزء 1 — تثبيت الحالة الحالية والمتطلبات

**الحالة:** فحص محلي موجود؛ متطلبات التفعيل مفتوحة.

- [x] حصر الملفات المعدلة والحفاظ على شغل الفريق السابق.
- [x] تسجيل نتائج التنفيذ السابق والأخطاء الموجودة في تقرير التحقق.
- [x] إعادة Teams baseline قبل كتابة هذه الخطة: 70 اختبارًا ناجحًا في 9 ملفات.
- [ ] المالك يراجع وينفذ SQL بالترتيب الموضح في دليل التشغيل، ثم ينفذ استعلامات التحقق للقراءة فقط.
- [ ] تأكيد وجود جداول الجلسات والتسجيلات والطابور وسجل الحضور وربط العذر بجلسة التعويض في البيئة المقصودة.

**ملفات SQL للمراجعة:**

- [session_results_archive.sql](sql/session_results_archive.sql)
- [session_attendance_reporting.sql](sql/session_attendance_reporting.sql)
- [attendance_absence_recovery.sql](sql/attendance_absence_recovery.sql)، إذا لم يكن مطبقًا بالفعل.

**شرط إغلاق الجزء:** دليل تحقق من البيئة المقصودة، مع عدم إعادة حساب الحضور التاريخي أو فقدان روابط الأدلة. لا تُشغَّل واجهة تعتمد على الجداول الجديدة قبل تجهيزها.

## الجزء 2 — مطابقة الحضور وحفظه في جدول الغياب

**الحالة:** منفذ محليًا واختُبرت القواعد بمعزل عن قاعدة البيانات؛ كتابة السجل الحقيقي لم تُختبر.

- [x] ربط Join بالمستخدم الموثق والجلسة المحددة، ومقارنة ذلك بتقرير Teams.
- [x] حساب المدة من الفترات، وتجميع إعادة الاتصال، ومنع تكرار الوقت عند استخدام جهازين.
- [x] حفظ حالة التقرير والهوية غير المعروفة، ومنع تحويل تقرير ناقص إلى غياب مؤكد.
- [ ] اختبار تكامل السجل باستخدام بيانات صناعية: 0، 179، 180، 181 ثانية، ثم إعادة اتصال وفترات متداخلة.
- [ ] التحقق من أن ضغط Join دون حضور يبقى `0` بعد اكتمال التقرير، وأن الدخول لجلسة لا يضيف الطالب لباقي جلسات السلسلة.
- [ ] اختبار تعدد صفحات التقرير، وفشل صفحة وسطية، وتأخر التقرير، والمشارك الذي لا يمكن ربط هويته.
- [ ] مطابقة شاشة الأدمن وCSV وسجل الحضور وتقارير الطالب دون ازدواج أو تغيير بيانات طالب أو مجموعة أخرى.

**شرط إغلاق الجزء:** كل نتيجة لها دليل Teams صحيح، والبيانات المجهولة ظاهرة للمراجعة، والسجل الفعلي يطابق الحالات المتوقعة.

## الجزء 3 — المزامنة الخفيفة والعمل في الخلفية

**الحالة:** الطابور والعامل منفذان واختُبرا بمضاعفات اختبار؛ تشغيل المجدول لم يُفعّل.

- [x] زر Sync يطلب مهمة قصيرة؛ تحميل الفيديو والتقرير لا يحدث داخل طلب الصفحة.
- [x] طلبات القراءة تعرض المحفوظ؛ لا استدعاءات Graph أو نقل ملفات عند فتح النتائج.
- [x] إعادة المحاولة وتأخيرها، ومنع تنفيذ نفس المهمة بالتوازي، وإظهار الفشل الجزئي.
- [ ] اختبار فعلي لطول طلب Sync وعدد طلبات فتح الصفحة، ومقارنتها بالحالة الحالية دون نقل ملفات في الطلب.
- [ ] إيقاف عامل أثناء العمل ثم استئنافه؛ تشغيل عاملين؛ إعادة Sync؛ وصول طلب جديد أثناء تنفيذ مهمة قديمة.
- [ ] التأكد من إعادة استخدام الملفات الجاهزة، ووصول الملفات المتأخرة، وتجديد تصدير حضور جلسة قديمة بعد Catch-up.
- [ ] المالك يفعّل مسار جدولة واحدًا كما في دليل التشغيل، ويتحقق من عمله ومن استمرار مزامنة اجتماعات الكوتش.

**شرط إغلاق الجزء:** دليل على عدم تكرار المهام أو الملفات، وظهور الأعطال وإمكانية استعادتها، وطلبات واجهة لا تنتظر Graph أو نقل الفيديو.

## الجزء 4 — تنظيم Azure وحفظ الملفات

**الحالة:** الكونتينر الخاص أُنشئ وتم التحقق من خصوصيته؛ نقل وتشغيل ملفات حقيقية لم يُختبرا.

```text
session-recordings/
  module-name_module-id-hash/
    group-name_group-id-hash/
      session-01_occurrence-id-hash/
        recording-artifact-id.mp4
        transcript-artifact-id.vtt
        transcript-artifact-id.txt
        attendance.csv
        teams-attendance-original.json
```

- [x] تنظيم منفصل للمادة والمجموعة والجلسة، مع معرفات تمنع تعارض الأسماء.
- [x] نقل متدرج للفيديو، وإعادة استخدام الملف بعد انقطاع العامل، وروابط قراءة مؤقتة لملف واحد.
- [x] اختبارات معزولة لتنظيف CSV من الصيغ، وحفظ النص والمتحدثين، وعدم تغيير مدة روابط المستندات الأخرى.
- [ ] نقل تسجيل اختباري مصرح به؛ فحص MP4 وVTT وTXT وCSV وJSON ومطابقة الجلسة والبيانات.
- [ ] تشغيل فيديو طويل والتنقل داخله بعد أكثر من 15 دقيقة؛ اختبار انتهاء الرابط وإعادة فتح الصفحة.
- [ ] اختبار أكثر من مقطع تسجيل لنفس الجلسة، وإعادة المزامنة دون ملفات مكررة.
- [ ] إثبات منع الوصول دون صلاحية، وعدم كشف مفاتيح أو روابط Graph، وفشل النقل ظاهر ولا يُعرض كنجاح.

**شرط إغلاق الجزء:** الملفات محفوظة خاصة بالمسار الصحيح، قابلة للعرض والتصدير للمصرح لهم، وإعادة المحاولة لا تفقد أو تكرر الأدلة.

## الجزء 5 — واجهة الأدمن ومعاينة المحتوى

**الحالة:** منفذة واختبارات تفاعل DOM ناجحة؛ الفحص المرئي في متصفح فعلي مفتوح.

- [x] مدخل Sessions & Recordings من Module Builder وModule Workspace وتفاصيل اجتماع Teams.
- [x] قائمة جلسات خفيفة؛ تفاصيل التسجيل والنص والحضور تُقرأ عند فتح الجلسة.
- [x] تصدير الحضور والنص، ومعاينة الموديول أو المكون باستخدام عارض محتوى الطالب.
- [ ] فحص بصري بأحجام شاشة مختلفة، والتمرير، ولوحة المفاتيح، وإغلاق النافذة والعودة لموضع العمل.
- [ ] اختبار حالات التحميل، وعدم وجود ملفات بعد، والمعالجة، والفشل الجزئي، وإعادة المحاولة.
- [ ] مراجعة كل نوع محتوى مستخدم فعليًا: فيديو، مستند، رابط، Quiz، Reflection، وSCORM إن وُجد.
- [ ] مراقبة الشبكة أثناء Preview: لا حفظ تقدم أو درجات أو إجابات أو حضور، ولا فقد لتعديلات الموديول غير المحفوظة.

**حد معروف:** المعاينة تعرض المحتوى؛ ليست انتحالًا لحساب طالب بعينه أو درجاته. حزم SCORM التي تتطلب LMS runtime تحتاج تحققًا منفصلًا من توافق المعاينة.

**شرط إغلاق الجزء:** الأدمن يجد نتائج الجلسة ويصدرها ويعاين المحتوى بوضوح، دون آثار على سجلات الطالب أو عمله غير المحفوظ.

## الجزء 6 — تجربة الطالب والصلاحيات

**الحالة:** منفذة واختبارات محلية ناجحة؛ السيناريو الحقيقي لم يُختبر.

- [x] عرض التسجيل داخل Live Session الأصلي بمشغل مدمج، والنص عند جاهزيتهما.
- [x] إغلاق Join عند نهاية الجلسة حتى لو الصفحة ظلت مفتوحة، دون polling.
- [x] قصر البيانات على حضور الطالب نفسه، والتحقق من هويته وإسناد الموديول على الخادم.
- [ ] اختبار الطالب المسجل بالموديول، والطالب غير المسجل، وطالب من مجموعة أخرى، وغير المسجل دخوله.
- [ ] تجربة الرابط المباشر للملف والنتائج مع مستخدم غير مخول، وليس إخفاء الزر فقط.
- [ ] اختبار قبل نهاية الجلسة وعندها وبعدها، والمناطق الزمنية، وإغلاق Join من الواجهة والخادم.
- [ ] التحقق من عدم ظهور أسماء أو حضور زملاء الطالب، واستمرار تقدم المحتوى والواجبات القائمة كما هو.

**شرط إغلاق الجزء:** الطالب يشاهد المحتوى المسموح له فقط، ويجد حالة واضحة عند انتظار التسجيل، ولا يستطيع استخدام Join بعد انتهاء الموعد.

## الجزء 7 — العذر وCatch-up مع الكوتش

**الحالة:** الربط منفذ والقواعد اختُبرت معزولة؛ التكامل مع سجلات العذر والكوتش مفتوح.

- [x] قبول العذر يبقي الحضور `0` مع توضيح أنه بعذر ويحتاج Catch-up.
- [x] ربط جلسة التعويض بالطالب والغياب المحدد؛ تحويل الحضور عند إتمامها وتأكيد الكوتش.
- [x] الحفاظ على دليل الغياب الأصلي ونتيجة التعويض عند إعادة المزامنة.
- [ ] المرور من زر الاستئذان الموجود إلى الموافقة، ثم حجز وربط جلسة التعويض وإتمامها.
- [ ] تأكيد أن الحجز فقط، أو المشاهدة فقط، أو جلسة ملغاة/غير مكتملة لا تغير الحضور.
- [ ] رفض ربط جلسة تخص طالبًا آخر أو جلسة غير Catch-up، واختبار صلاحيات الكوتش.
- [ ] إعادة تأكيد الإتمام وإعادة Sync: لا ازدواج؛ تظهر النتيجة الصحيحة في سجل الحضور وتقرير الأدمن والتصدير.

**شرط إغلاق الجزء:** العذر وحده لا يساوي حضورًا، والتعويض المؤكد يُحدّث السجل مرة واحدة مع بقاء التاريخ والأدلة.

## ما نبدأ به عند استئناف التنفيذ

1. مراجعة البند المفتوح التالي مع الحفاظ على الكود الموجود؛ لا إعادة تنفيذ الأجزاء المنتهية بلا سبب.
2. تنفيذ ما لا يعتمد على قاعدة البيانات: مراجعة الكود، الاختبارات المعزولة اللازمة، وتجهيز حالات التحقق.
3. متطلبات الانتقال للتكامل: تأكيد المالك تنفيذ SQL، وبيئة اختبار محددة ومصرح بها، ومتصفح متاح. لا تشغيل خادم أو اختبارات كتابة على قاعدة غير موثقة.
4. بعد توافر المتطلبات: الأجزاء 2–4 للبيانات والمزامنة والتخزين، ثم 5–7 للأدمن والطالب والتعويض، ثم بوابة الجزء 8.
